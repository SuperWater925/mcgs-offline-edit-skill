# 原生窗口、控件与样式

`scripts/native`是纯字节库，不加载厂商程序/DLL，不打开数据库。控件生成在`tools/mcgs_ui.py`：用当前工程安全导出的真实同类记录作模板，逐类解析、修改和回环，见[界面工具](ui-tools.md)。

## 修改前后不变量

窗口记录使用`MCGS-SET DOCUMENT;VERSION 01.00`原生标记，控件type+带长度payload，尾部包含窗口设置和事件。初次解析必须字节精确回环；样式修改之后反向恢复应与原输入相等，未列字段原样保留。

`CommonEnvelope`把已有动画原始字节保留，样式编辑时临时投影为空动画再恢复；不能因底层简单解析器不识别动画而删动画。成组控件子节点必须递归覆盖，避免只改最外层Rect造成文字与图片错位。

字体高度、字体实际着墨、行高和文字框共同验收；字体字段改大不保证可读。注意COLORREF是BGR字节顺序。LOGPEN/LOGBRUSH各自有样式、颜色及其他成员，不能只凭截图写错偏移。多态按钮文字/图片子项内有相对矩形与比例双精度值，调整外框时同步已证子字段并保留业务条件。

窗口背景必须用原生背景/底板和正确刷子样式。填充色字段变了但brush仍是空心、某输入框外观模式仍走图片、或者有不透明底板挡住时，原厂视觉可能不变。核对实际原生样式模式及层次，不能以离线渲染“好看”替代原厂可见性。

## 事件与缓存

标准按钮`click_script`历史接口实际写原生松开/release脚本，受原生安全条件控制；不要改写为通用Click事件，后者可能绕过按钮安全。

策略调用使用`!SetStgyMode(本地策略对象)`裸对象参数，不能写成字符串`!SetStgyMode("本地策略对象")`。中文对象/策略名必须真实注册并绑定，不能以文本变量假冒原生对象。

只清实际改动的源码节点缓存。`EventDispatch.set_source`在源码变化时清对应compiled/tail数组，未变事件应保持缓存；窗口事件的三份缓存分开处理。原厂保存可能重新产生缓存或调整尾部换行，接收新版本后应复读对比，不因为hash不同就回退用户保存。

脚本语法以目标原厂编译器为准；不能把历史 Stu 工程的 `ElseIf/Select Case` 限制套到所有 Stu/Pro 工程。单行`If 条件 Then 语句`不需要`EndIf`，检查块平衡时只数以`Then`结尾的`If`行。设备命令Read/Write一条可以读写多项，用分号分隔。

## 原厂运行时实测

以下是McgsStu 3.5.3在实际工程中由实机截图或运行证实的规律。`tools/离线预览.py`已按其中能做到的处理；预览与原厂不符时，以原厂为准。

离线预览与原厂不一致：
- 0x5028/0x502a多态按钮（CDrawMulBtn/CDrawMulDis）的common画笔，也就是边线，原厂运行时不画，离线预览会画。需要边线时，在按钮之上叠2–4像素宽的0x5004填充矩形。
- 0x5008文字开了common画刷/画笔门控，原厂会画底色和边框（实机报警数字灰底证实）。只要文字时关掉门控。
- 离线预览不认可见条件：同位叠放的几种状态在图里全部叠出，运行时只显示条件成立的那一个。

可见条件：`可见动画归档.添加可见条件`支持0x5004/0x5008/0x5025/0x503d，实机生效。配方表的可见表达式在`RecipeCore.fields['visible_expression']`，改后清`m94_cache`。

文字与数值：
- 原厂文字左右各留约6像素，框宽不足会裁掉末字。静态文字框至少“字宽+24”；带CAniOutput的动态文字（如设备返回的名称）按最长实际值留宽，不按占位文字收窄。
- 对齐：文字控件style与appearance_prefix[1]同值，0左/1中/2右；输入框properties[3]同规则，其中左对齐尚未经原厂确认。
- 恒禁用（使能表达式`'0'`、变灰样式1）的显示框，原厂画灰字。
- 显示框小数位有两处u32：元数据+50与外观+36，要一起改。
- 改绑显示框：`InputRecord.variable`改名，`properties[5]`=对象ID，`properties[6]`=对象类型，清`expression_cache`后回读核对。数值显示只接对象类型1/2，字符显示接类型3。

配方表（0x503d外部构件，RecipeCore）：
- 列值`values[0]`类型、`[1]`可见、`[2]`宽、`[5]`小数位。列宽总和要比表宽少约30像素，否则出横向滚动条。
- 焦点颜色：`m78`焦点整行底，`m80`焦点单元格底，`m88`焦点字色；普通行底`m60`，字色`m50`。三项焦点色设成普通色，就得到不高亮的浏览表。

## 窗口与对象

- 新建窗口：克隆同层窗口的`WindowSettings.clone(ID, 名称)`（`properties[0]`=ID，`[1]`=名称），事件用`窗口事件归档.设置窗口事件(tail, 打开, 循环, 退出, 周期毫秒)`重设。数据库要新增一行WndUser，六列`iID/strName/strNote/lbObjects/iDeleteFlag=0/iCompileFlag=0`。本包`apply`不做insert，用`tools/新增窗口事务.ps1`，见[界面工具](ui-tools.md#tools新增窗口事务ps1)。
- 公共窗口：每个用户窗口`event_tail`末尾78字节处`0e 00`之后的3个i32是公共窗口编号槽，-1为空；底板和侧栏靠它叠加。删窗、换底板时，名称引用和这些编号都要查。
- 主控窗口`WndControl/1`存启动窗口列表：u16个数+CString名称，u16个数+u32窗口号，后接内存窗口列表，没有总长字段。
- 删控件或改名：查同窗、跨窗和策略源码里的`窗口名.控件名`引用。用正则查时加前后字界，避免把说明文字（如“信息.csv和工艺段”）当成引用。
- 从旧版本导出原样复制控件可行，前提是它绑定的对象ID在当前工程仍是同一对象。
- 原厂编译会重生成`System`表的`ObjPointerRule`、`VARCOLLECTTABLE`、`VARCOLLECTTABLEWND`。离线改动不用碰它们；新页面和新绑定要原厂编译后才进入采集表，不要离线伪造。

## 无图片警告

原项目曾把`(3,0,0)`当“无图”，原厂重载会把它规范化为无名称图片引用，启用时触发24146警告。正确修复按控件类别关闭真正图片门控或移除空图片子项：标准按钮、输入框两份外观门控、多态控件状态图片各自有格式。保留有效图片、所有状态/填充/文本与动作。不要把所有图片清空，也不要只把路径写空。

## 原厂界面/API验收

本库的解析和静态证据只证明已证字节字段。接收电脑用对应家族的McgsStu / McgsPro打开实际输出、全工程检查、保存重开，检查图像警告、文字、背景、按钮安全、导航和目标构件；需要本机模拟时用离线设备隔离副本。离线字段预览不是原厂截图。

## Stu / Pro 共用适配

软件大小版本与控件数值头只记录，不设置发行版本白名单。窗口、设置、事件和公共封套共用结构适配；动画先投影、修改后恢复，未知动画保留。已补旧内嵌图片、CTriggerEvent、配方0/12字节尾、输入框双层计数和实际报警/下拉框结构。详见[Pro适配](pro-adapter.md)与[统一验证](unified-validation.md)。
