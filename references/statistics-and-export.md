# 原生时间范围、原始CSV与可调存盘

## 已证API语义

| 对象/方法 | 已证语义 |
| --- | --- |
| SaveDataBrowser.DataRows | N为真实数据行数，不包含表头 |
| SaveDataBrowser.GetCellValue(int行,int列) -> string | 行0为表头；真实数据行1…N；时间列号按实际列定义 |
| 存盘浏览控件.SetTimeDialog | 原生同一个对话框中选择开始与结束；保留原生入口与私有筛选 |
| Refresh | 无返回值的原生方法，单独调用，不能赋值或把返回码当成功证据 |
| !ExportHisDataToCSV | 全局原始历史导出，启动返回与异步最终完成分开 |

**行号：**首条用`GetCellValue(1,时间列)`，末条用`GetCellValue(N,时间列)`。用`(0,列)`会读到标题“时间”（长度2），用`N-1`会漏最后一行；不要把这个错误解释成“没有勾选显示年月日”。N=0不读端点；空串是尚未就绪，格式不符另报无效时间。

原生`SetTimeDialog`一次选起止，不能拿历史曲线的`ShowTimeDialog`替代：历史曲线与存盘浏览是不同原生对象，名称相近不表示API等价。也不能用自建的“统计开始/结束时间”全局变量假冒原生控件的私有筛选；原生对话框改了条件，这些变量可能毫无变化。

## 用首末记录作导出范围

一种可行的桥接：用存盘浏览当前数据的首末完整时间作为全局导出的时间范围。准确名称是“准备时已有记录的时间覆盖范围”；它不是原生私有筛选的公开回读，也不是数据库事务快照。

- 准备时在统计页、N>0，读首末，复读N和两个端时间，再做最终N检查；读不到、记录变化、格式无效就结束准备并提示，不扩到全历史，不循环等待凑数据。
- 先校验`YYYY-MM-DD HH:MM:SS`格式、分隔符、闰年/月天数/时分秒，再用实现中的日期转换做完整回环校验。可接受的年份范围、时区前提由工程自定，不是厂商通用结论。
- 升序/降序都取两个端时间的最小/最大；单条或同秒多条允许起止相同，不私加一秒。
- 前提是固定记录集、仅时间筛选、时间排序。持续写入时成员集合可能变化；加入数值条件或非时间排序时要重新设计或拒绝该模式。

## 原始数据导出与真实完成

单次导出上限是方案参数，不是所有版本的厂商最大值。调用保持原始值导出，不能把显示格式化后的表格逐格写CSV冒充原始历史数据。调用形态示例（参数以当前厂商函数签名为准）：

```text
返回码 = !ExportHisDataToCSV(文件路径,"存盘组名","",开始时间,结束时间,上限条数,1,"",进度对象,控制对象)
```

- 启动返回0只表示任务已开始。最终由原生传址的控制/进度对象判断完成：`control=1`才走结束判定，同时检查取消标志和负错误码。不能凭文件存在、文件变大、固定延时或点了按钮就报“已完成”。取消状态单独保存，避免控制位复位后误报成功。
- 达到上限时提示缩小范围分批导出；N只用来定位末行，不能拿N代替上限去“补满下一批”。
- 每次生成唯一文件名并查重，不覆盖已有文件。路径准备、无U盘、目录不可写、取消、启动错误与最终错误各自准确报告。导出运行中允许切页面，但不要读已失效的窗口引用。

## 可调历史存盘周期

按工程定的粒度和范围校验周期（检查NaN、边界、粒度），换算后调用`!ChangeDataSave`；失败不宣称生效。

应用成功后更新“生效周期”，`!SaveSingleDataInit(周期对象)`和`!FlushDataInitValueToDisk()`分别检查返回码；“已生效但初值/磁盘保存失败”与“全部保存完成”要区分。启动策略恢复保存值，重启后核对实际周期。
