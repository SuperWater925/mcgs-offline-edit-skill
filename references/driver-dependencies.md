# 原厂检查的驱动缺失处理

原厂只显示第一项缺失设备时，修好后可能暴露下一项；一次错误清零前须重新执行全工程组态检查。只检查设备窗口可能仅覆盖设备，应回工作台检查整个工程。文件侧审查通过不能代替驱动依赖检查。

1. 从当前工程 WndDevice 读取实际驱动名及路径，只提取依赖信息，不输出设备凭据/账户或改设备表。工程可能保留另一台电脑的 C:/D: 绝对路径；先核对当前安装根目录的同一相对路径和原厂实际加载模块，不能批量改地址或删除设备。
2. 优先找本机原项目的驱动目录、原始压缩包及可信厂商来源。`.ui` 本例是 Windows PE 组态插件，不是普通 XML；同名文件不构成兼容证明。配套 DLL、ARM 库、语言库和附带依赖按真实包一起保全，记录来源、版本和 SHA256。
3. 对已有文件先比较，保留本地修改；优先在独立原厂测试目录复验。安装缺失文件时保留原有驱动，记录新增清单。不要复制运行时符号缓存、临时文件、当前工程账户或凭据，也不要修改启动器/授权/运行时限机制。
4. 使用原始安全副本和修改副本分别打开、全工程检查，对照错误及警告。只有新增库真正被编辑器加载、缺失错误消失，才记完成。物理通信仍独立验收，不能自动运行含真实设备的用户工程。
