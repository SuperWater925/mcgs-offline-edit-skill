# 项目约定（模板）

技能本身不带任何具体工程的资料。接手一个工程后，在工程自己的文件夹里建一份“项目约定”，每次开工先读它；不要写回技能包。建议记这些：

## 当前主线

- HMI主线文件的路径、SHA、记录时间，以及结构截面：表数、窗口数、对象数、配方组数、策略与触发器数。数字只是截面，每次以实际路径重新取。
- 版本链：每一版的底稿（用户编译保存后的哪个文件、SHA）、改了什么、说明文档在哪。用户在编辑器里保存过的版本才是下一轮底稿；带候选/草稿/仿真字样的文件不能当主线，也不能拿来覆盖主线。
- PLC主线工程路径。PLC工程通常是整个目录，只复制工程文件不能迁移或恢复。
- 运行配方等运行时数据的位置。它们和MCS是两层数据，改动前一起保全。

## 界面结构

- 画面分辨率；底板窗口、侧栏窗口的编号，各页面挂了哪些公共窗口。
- 切换页面走哪个策略（白名单、高亮变量的命名规则）；新增页面要在哪里登记。
- 导航按钮激活态的规则，可以直接写成离线预览用的`--active-map`文件。
- 有特殊约定的对象和策略：例如某个对象区分表格在哪一页、离开某页时要关什么。

## 业务语义

- 当前生产语义以实际源码为准；旧变量注释或历史文档与之不符时，记下哪条已过时。
- 文件格式（例如工艺CSV有几列、列顺序）、容量上限、时间范围等实施参数，注明是本工程定的，不是厂商限制。

## PLC与通讯

- 驱动、协议、端口，公开变量表来源。
- HMI与PLC的握手方案、通信变量表；类型码按驱动实测写（见[PLC对接](plc-handoff.md)）。

## 用户约定

- 授权边界：能否操作原厂编辑器/仿真器，是否允许就地修改，能否下载PLC、写设备。
- 命名偏好（例如变量用中文）、界面偏好（例如先出效果图、不重复信息）、交付方式。

## 工程自带工具

工程里如果另有生成脚本、渲染器配置等，记路径和用法，使用前确认文件仍在。
